# 0004 面板坐右侧栏，不坐左侧栏

- 日期：2026-11-22
- 状态：**已实现**（v0.2.0；实现细节见 [subsystems/client-sidebar.md](../subsystems/client-sidebar.md)）

## 背景

用户希望能通过侧边栏操作/查看本体层，而不是每次都让 agent 调工具、再把结果读成一堆文本。

DSH 有两处常驻 UI 座位，二者互斥地影响可见性：

| 座位 | 注册点 | 打开后 |
|---|---|---|
| 右侧栏 | `sidebar.right.pane.tab`（keyed，每会话布局） | 与浏览器/文档/文件并列成标签页；中栏仍是会话 |
| 左侧栏 global panel | `sidebar.panellist`（图标）+ `main`（keyed，同名 key） | 面板**占据整个中栏**；此时右侧栏整体不可见 |

## 决策

坐**右侧栏**。

## 理由

1. 本插件的使用场景是「对话 + 旁路观察」：agent 在会话里建本体，用户在旁边看版本与计数变化。右侧栏标签页正好是「不打断对话的第二块视图」。
2. 左侧栏面板会占掉中栏，而中栏是全局面板选择（`activePanelId`），一旦被占，DSH 右侧栏按宿主设计整体隐藏——用户会同时失去文件树/文档预览。为了看本体而牺牲整个右栏，不成比例。
3. 右侧栏每会话独立布局、可浮动可分离，符合「同一个本体、多个会话同时观察」的用法。

## 已知代价

- 中栏不是会话时（例如用户在左侧面板式插件里工作），右栏不可见 → evo 面板一起消失。这是宿主行为，不接受为此改造。
- 右侧栏的正文由浏览器侧渲染，拿不到 MCP 工具的句柄，只能走 Host → 命令桥 → Client 的数据通路。

## 后续

若落地后发现「用户期望面板随数据自动刷新」这个需求强烈，再追加 ADR 讨论事件推送方案，而不是改座位。当前实现是显式刷新（挂载时一次 + 「刷新」按钮），并用 `keepMounted: true` 避免切标签页就重拉。
